# Taskeer

Aplicación nativa Android (Kotlin + Jetpack Compose) para gestionar tareas kanban. Esta versión es offline-first con datos locales; no incluye sincronización. Existe una capa de cliente HTTP que hoy solo usa el inicio de sesión opcional (ver «Cuenta e inicio de sesión»). Los avisos y recordatorios usan notificaciones locales del sistema.

## Requisitos

- JDK 25 (Android Studio JBR o compatible)
- Android SDK con la API 37 disponible; la ruta del SDK se define en la configuración local del entorno, que no se versiona
- Android Studio / Gradle

## Cómo compilar y ejecutar tests

```bash
./gradlew :app:testDebugUnitTest              # tests JVM
./gradlew :app:lintDebug :app:assembleDebug   # lint + build de depuración
```

La puerta de verificación son los tests JVM en `app/src/test/java/**` (JUnit 4). Los tests instrumentados (`app/src/androidTest/**`) requieren emulador y no forman parte de la puerta de verificación.

## Funcionalidades actuales (verificadas)

- **Arquitectura limpia**: capas `domain/`, `data/`, `di`, `ui/`. `domain/` es Kotlin puro (sin Android). `ui/` no accede a almacenamiento.
- **Contenedor de dependencias manual**: `di/AppContainer` creado por `TaskeerApplication`.
- **Navegación**: la app arranca en `Mi día`. Las pantallas de sección no tienen barra inferior: un **botón Home flotante** (esquina suave del tema) lleva al hub **Home** desde las pantallas de sección y desde el tablero, y desde Home una **barra de navegación estándar de Material 3**, anclada al borde inferior del hub, con iconos y nombres completos, abre `Mi día`, `Próximos 7 días`, `Todas las tareas` y `Calendario`. Home no es una pestaña: la barra no marca ninguna sección como seleccionada. Las pantallas de detalle (columnas, avisos, Configuración) usan flecha de vuelta. Hay restauración/recorte de estado según política de navegación.
- **Tema** (se configura en la pantalla `Configuración`, ya no en la barra superior): claro/oscuro/automático (`LIGHT`/`DARK`/`AUTO`). Origen de color a elección del usuario: **paleta de marca** o **Material You** (color dinámico). En API < 31 no se ofrece la opción dinámica; por defecto se usa Material You si el dispositivo lo soporta, si no se usa la paleta de marca. Las preferencias del tema se persisten con DataStore.
- **Tableros (CRUD local)**: los tableros se ven y se crean en el hub Home (ver «Home»). Se pueden **crear** (Card «+» con un diálogo), **renombrar** y **eliminar** (desde el menú de tres puntos del propio tablero, el eliminar con confirmación). El nombre se recorta y no puede quedar vacío (se rechaza con un error de validación visible); la lista se ordena por fecha de creación y se actualiza de forma reactiva. Al tocar un tablero se abre su **tablero kanban**. El borrado es lógico (soft delete): la fila permanece en la base de datos pero el tablero deja de listarse. Toda la funcionalidad es local, sin red.
- **Columnas del tablero (CRUD local)**: al crear un tablero se **siembran tres columnas por defecto** («Por hacer», «En progreso», «Hecho»; la última marcada como columna de cierre) en la misma operación atómica que crea el tablero. En la pantalla de columnas se puede **crear** (se añade al final), **renombrar**, **reordenar** con «subir»/«bajar» y **borrar**. El nombre se recorta y no puede quedar vacío; alta y renombrado se deshabilitan con el campo vacío y los movimientos se deshabilitan en los extremos de la lista. El orden se persiste por posición y se mantiene tras recargar. El borrado es lógico (soft delete) y recompacta las posiciones de las columnas restantes; el dominio rechaza borrar una columna que tiene tareas (también cuentan las borradas lógicamente) y muestra el error en pantalla. Toda la funcionalidad es local, sin red.
- **Tareas del tablero (CRUD local)**: dentro de la pantalla de columnas, cada columna ofrece **Añadir tarea** y lista las tareas que le pertenecen; cada tarea tiene una acción **Editar** que abre el editor de tarea (ver «Editor de tarea»). El editor permite fijar **título** (obligatorio: se recorta y no puede quedar vacío; con el campo vacío el botón de guardar queda deshabilitado y el dominio rechaza la escritura con un error de validación visible), **descripción** (opcional), **prioridad** (conjunto cerrado de cuatro valores — Baja, Media, Alta y Urgente — con Media por defecto, que se elige en un **desplegable**), **asignado** (el usuario local, «Yo»; el editor ya no ofrece «Sin asignar» y una tarea creada o editada sin asignado explícito queda asignada a «Yo») y **fecha límite** (opcional). La fecha límite se captura con un selector de fecha y otro de hora **en la zona horaria del usuario** y se guarda convertida a **UTC**; al reabrir una tarea existente la fecha se muestra de nuevo en la zona local. La tarea nueva se añade al final de su columna y el editor **no** ofrece selector de columna: la tarea pertenece a la columna donde se crea. El **borrado** es lógico (soft delete): la fila permanece en la base de datos marcada como borrada y deja de listarse, sin renumerar el resto. Toda la funcionalidad es local, sin red.
- **Tablero kanban**: al abrir un tablero se ven sus columnas, en orden, con las tareas de cada una como tarjetas (columna vacía con su indicación). Cada tarjeta muestra el título, la **prioridad**, la **fecha límite** (en la zona horaria del usuario), el **asignado** («Yo» para el usuario local) y una **estrella** (icono relleno/contorno) pulsable que marca o desmarca la tarea en «Mi día»; la estrella solo se ve rellena si la marca es **de hoy** (una marca de un día anterior se muestra vacía y volver a tocarla la añade a hoy) (el toque no inicia arrastre ni abre el editor). Con una **pulsación larga y arrastre** una tarjeta se **mueve a otra columna** (entre tarjetas o en una columna vacía) o se **reordena dentro de su columna**; soltar en el mismo sitio o fuera de toda columna no cambia nada. El movimiento se persiste de forma atómica con posiciones contiguas (se renumeran origen y destino, normalizando huecos) y se mantiene al reabrir la app. Mientras se guarda, la tarjeta se ve ya en destino; si el movimiento falla (tarea o columna inexistente o borrada, columna de otro tablero, índice fuera de rango) se revierte al orden guardado y se muestra el error. Pulsar una tarjeta abre el editor, «Añadir tarea» crea la tarea en esa columna y el botón «Columnas» abre la gestión de columnas. El botón «Añadir columna» abre un diálogo para crear una columna nueva (al final) sin salir del tablero, con el mismo recorte y validación del nombre que la pantalla de columnas. La pantalla de columnas incluye un botón «Volver» que regresa al tablero. Toda la funcionalidad es local, sin red. El gesto de arrastre está cubierto por tests de la lógica de destino, pero no por una prueba instrumentada.
- **Subtareas (CRUD local)**: el editor de una tarea existente incluye una sección de **subtareas** donde se puede **crear**, **editar** el título, **marcar como completada** (y desmarcar) y **borrar**; estos cambios se guardan al instante, y las filas entran, salen y pasan de lectura a edición con animación. Al **crear una tarea nueva** la misma sección permite añadir subtareas como borrador (título, fecha límite y asignado opcionales; no se pueden completar durante el alta) que se guardan junto con la tarea. El borrado es lógico (soft delete) y **borrar una tarea borra también sus subtareas** en la misma operación. Cada subtarea admite además una **fecha límite** y un **asignado** opcionales (sin asignar o el usuario local; las subtareas conservan «Sin asignar»), editables desde la propia sección. El repositorio expone el **progreso** de las subtareas de una tarea (total y completadas) como flujo reactivo. Toda la funcionalidad es local, sin red.
- **Completar tareas con una casilla**: cada tarea del tablero kanban, de las listas y de `Mi día` tiene una **casilla de un toque** (con descripción accesible «Completar tarea» / «Marcar como pendiente» y área táctil de 48 dp) que la completa o la devuelve a pendiente; la tarea completada muestra el título tachado. «Completada» es un estado propio de la tarea (marca de fecha de completado, que se persiste en Room), independiente de la columna. Al **completar** una tarea de un tablero se mueve al final de la **columna de cierre** (la de menor posición si hay varias; si ya está en una, se queda) y se renumera la columna de origen; si el tablero no tiene columna de cierre, se marca en su columna sin moverla. Al **desmarcar** una tarea que está en una columna de cierre, vuelve al final de la **primera columna que no es de cierre**; si está en otra columna solo se limpia la marca, y si el tablero solo tiene columnas de cierre se rechaza con un error visible. Las tareas de una lista se marcan sin cambiar de sitio. Mover una tarea a (o desde) una columna de cierre, arrastrando o con «Asignar a tablero», también la marca o desmarca. Completar o desmarcar respeta el límite WIP de la columna destino (conflicto visible, sin cambios). Las tareas completadas **siguen en `Mi día` hasta el fin del día en que se completaron** (tachadas, al final de la lista), no cuentan como vencidas ni como tareas activas, y **no generan avisos** por fecha límite, resumen ni recordatorio manual; siguen contando en los contadores de columna del tablero. Repetir la misma acción no escribe nada. Las tareas que estaban en una columna de cierre al actualizar la app pasan a constar como completadas. Local, sin red. La migración sobre una instalación real, el dibujo de la casilla y el tachado no están cubiertos por pruebas automáticas.
- **Repetir tareas**: el editor (tarea nueva o existente) incluye la píldora **«Repetir»**, un menú desplegable con «No se repite», «Cada día», «Entre semana», «Cada semana», «Cada mes», «Cada año» y «Personalizada…» (la opción vigente aparece marcada; los campos de la personalizada, intervalo de 1 a 999, unidad día, semana, mes o año y, con semanas, los días de la semana, aparecen en línea bajo la píldora). Requiere **fecha límite**: sin ella la opción está deshabilitada con una indicación y al quitar la fecha vuelve a «No se repite»; el dominio rechaza una regla inválida o sin fecha con error visible. Al **completar** una tarea repetida se conserva y aparece **una sola vez** la siguiente, en el mismo sitio (misma columna o la misma lista; si la original pasa a una columna de cierre, la siguiente queda en la columna de origen, y completar sigue funcionando con la columna al límite WIP). La nueva fecha límite se calcula desde la fecha límite de la tarea (no desde el momento de completarla), **sin quedar antes de hoy**, en la **zona horaria del usuario** y conservando la hora local; en reglas mensuales y anuales el fin de mes se resuelve con un **día ancla** (31 de enero, 28 de febrero, 31 de marzo; 29 de febrero pasa a 28 en años no bisiestos). La siguiente copia título, descripción, prioridad, responsable, las **subtareas activas** (sin completar y con la fecha desplazada) y, si había, un **recordatorio manual con el mismo desfase** respecto a la fecha (si ya no es futuro no se crea). Desmarcar la original no crea otra y volver a completarla no duplica la siguiente. Se aplica igual al completar con la casilla, al arrastrar a una columna de cierre y al «Asignar a tablero» hacia una de cierre; la siguiente no se añade a Mi día. La tarea original y su siguiente se borran de forma independiente. La creación de la siguiente y la marca de la original se guardan en una única transacción. La lógica está cubierta por tests JVM; la migración sobre una instalación real, el cambio de horario de verano en dispositivo y el dibujo del selector **no están cubiertos por pruebas automáticas**.
- **Alta completa de tarea**: al guardar una tarea nueva se persisten juntas, de forma atómica, la tarea, sus subtareas y el recordatorio manual (hora futura); si algo falla no queda nada guardado, y cerrar la hoja sin guardar no deja ninguna fila. Local, sin red.
- **Editor de tarea (hoja inferior)**: crear o editar una tarea abre un **`ModalBottomSheet` con asa** que ocupa el **65 % de la altura de la ventana** (mínimo 400 dp; crece con el teclado), sin ruta nueva ni diálogo. La **cabecera** tiene **Cerrar**, un menú **⋮** («Borrar tarea» y «Descartar cambios», este último solo con cambios) y **«Guardar»** (deshabilitado con el título vacío o guardando). Debajo, la **ruta** «Mis listas › Lista» abre un selector para cambiar la tarea de lista; en una tarea de tablero muestra «Tablero › Columna» solo de lectura. Siguen un **título grande**, las **notas** y **siete píldoras**: Completar, Mi día, Fecha, Recordatorio, Repetir, Prioridad y Asignado, más la sección de subtareas. **Completar, Mi día, la lista, el recordatorio y las subtareas se guardan al instante** en una tarea existente (en una tarea nueva se envían al guardar); el resto de campos se guarda con **«Guardar»**. **Recordatorio**, **Repetir**, **Prioridad** y **Asignado** son menús desplegables; **Fecha** y «Elegir fecha y hora…» abren el selector de fecha y luego de hora **dentro de la hoja**, con transición animada. **Cerrar con cambios sin guardar** (Cerrar, velo, arrastre o «Atrás») pide **«Descartar» / «Seguir editando»**. **«Atrás» retrocede paso a paso**: primero el menú abierto, luego el panel o selector y después la hoja. **Borrar** se hace desde ⋮ y muestra el snackbar con **«Deshacer»**. Todo cambia con animación (paneles, valores de las píldoras, errores, bloques y filas) y es **instantáneo con «Quitar animaciones»** del sistema. Las píldoras y controles tienen descripciones accesibles y áreas táctiles de 48 dp. Local, sin red. La lógica del estado, de los paneles, de «hay cambios» y de las transiciones con escala 0 está cubierta por tests JVM; la **altura real al 65 %**, el **teclado y los insets**, el **foco**, las **animaciones**, **TalkBack** y el **giro de pantalla** no están cubiertos por pruebas automáticas.
- **Límites de validación**: el dominio rechaza con error de validación nombres de tablero de menos de 2 o más de 150 caracteres, nombres de columna de más de 100, títulos de tarea y de subtarea de más de 200 y descripciones de tarea de más de 5000 (tras recortar espacios).
- **Límite WIP y columna de completadas**: cada columna puede tener un límite WIP opcional, que se fija o quita desde la pantalla de columnas (campo «Límite WIP» y botón «Fijar»; vacío lo quita; el dominio rechaza valores menores que 1 con un error visible). Una columna con límite no admite más tareas activas que ese límite: **crear** una tarea en ella o **mover** una tarea desde otra columna se rechaza con un conflicto (el editor permanece abierto con el error; en el tablero la tarjeta vuelve a su sitio y se muestra el error). Reordenar dentro de la columna y sacar tareas de una columna sobrepasada siempre se permite, y las tareas borradas no cuentan. En el tablero cada columna con límite muestra un contador «n/límite», la columna de cierre se marca con un icono de completada y las tareas con fecha límite vencida (salvo las completadas) se muestran en color de error con descripción «Vencida: <fecha>». El dibujo del icono, el contador y la fecha vencida no están cubiertos por pruebas instrumentadas.
- **Mi día (diario)**: la sección `Mi día`, pantalla de arranque de la app, lista **solo lo marcado explícitamente para hoy** con la estrella (sin chips de filtro ni bloques forzados) y **se renueva cada día** según la **zona horaria del usuario** (el cambio de día, de zona u hora del dispositivo se detecta con la app abierta en como mucho un minuto, y los días de cambio de horario de verano duran 23 o 25 horas). Una marca de un día anterior no cuenta como de hoy. Cada fila (la fila de tarea compartida, ver más abajo) muestra título, tablero o lista, prioridad y fecha límite en la zona del usuario, y una casilla para completarla. El menú **«Ordenar»** (solo en esta pantalla) ordena por fecha límite (por defecto; sin fecha al final), prioridad o marcado reciente. **Las tareas completadas hoy no desaparecen**: quedan **tachadas al final de la lista** hasta el fin del día, y al día siguiente salen; desmarcarlas las devuelve a pendientes. La cabecera muestra siempre el **contador de tareas vencidas** (asignadas al usuario local, con fecha pasada, sin contar las completadas), exacto y sin tope, y se recalcula al cambiar los datos. **Tocar la fila abre el editor de tarea**; marcar o quitar de Mi día se hace con el deslizamiento o la hoja de acciones de la fila. Con la lista vacía y sugerencias disponibles, la pantalla muestra «Tu día está vacío» con el botón **«Ver sugerencias (N)»**; sin sugerencias invita a añadir una tarea. La marca se persiste en Room y sobrevive a reiniciar la app; el cambio de día no escribe en la base de datos. Las tareas de las listas (sin tablero) también aparecen. Toda la funcionalidad es local, sin red. La lógica está cubierta por tests JVM; el dibujo de la pantalla, el tachado, el toque de fila y el cambio de día o de zona en un dispositivo real no están cubiertos por pruebas automáticas.
- **Sugerencias de Mi día**: un **icono de foco con insignia** a la izquierda del menú de tres puntos, **solo en `Mi día`**, abre una **hoja inferior de solo lectura** con las tareas abiertas y visibles **no marcadas hoy** que están **asignadas a «Yo»** o tienen una **marca de un día anterior**, ordenadas: vencidas, de hoy, marcas anteriores y el resto. La insignia muestra el número de sugerencias (se oculta con cero y marca «99+» a partir de 100). Cada tarjeta tiene a la derecha dos botones de icono: **«+» (Añadir a Mi día)** y **«×» (Descartar)**; no se puede editar, borrar, deslizar ni abrir la tarea desde la hoja. **Descartar** oculta la sugerencia el resto del día y **reaparece al día siguiente**; **quitar de Mi día** una tarea sin completarla la devuelve a las sugerencias al instante; las completadas y borradas no vuelven. La hoja se cierra tocando fuera, con «Atrás» y con «Cerrar». Se **abre sola solo la primera vez que la app pasa a primer plano en un día nuevo**; la regla es estricta: ese día se consume aunque no haya sugerencias, no estés en `Mi día` o la app se abra desde un aviso. No hay parpadeo al añadir el primer elemento a una lista vacía. Local, sin red; el último día en que se ofreció se guarda en DataStore. La lógica (consultas, orden, descarte, insignia, regla de apertura automática, estado vacío) está cubierta por tests JVM; la apertura automática en arranque en frío, el velo y las animaciones, TalkBack, el parpadeo y el rendimiento con muchas sugerencias **no están cubiertos por pruebas automáticas**.
- **Próximos 7 días**: sección accesible desde Home. Muestra una **sección desplegable por cada uno de los próximos 7 días** (según el día actual en la zona del usuario), cada una con su propio botón **«+»** para añadir una tarea con la fecha de esa sección. Lista las tareas no completadas ni borradas con fecha límite (también las de listas), con la fila de tarea compartida: la casilla completa la tarea, tocar la fila abre el editor. Sin tareas muestra un estado vacío. Se reagrupa al cambiar el día o la zona horaria. Local, sin red. La lógica está cubierta por tests JVM; el dibujo de la pantalla y la navegación en dispositivo no están cubiertos por pruebas automáticas.
- **Todas las tareas**: sección accesible desde Home que agrupa las tareas pendientes con fecha límite en **«Hoy»**, **«Mañana»** y **«Próximamente»**, y las que no tienen fecha en **«Algún día»**. Usa la misma fila de tarea compartida y las mismas acciones por fila. Local, sin red; sin pruebas automáticas del dibujo.
- **Píldora de alta flotante**: las pantallas de sección (`Mi día`, `Próximos 7 días`, `Todas las tareas` y cada lista) muestran una **píldora flotante** compacta con un campo de **título** y un botón de **enviar** para crear una tarea al instante (en `Calendario` pasa a ser «Añadir evento», ver «Calendario»). Al abrirla se **expande recta, a todo el ancho de la pantalla y pegada al teclado y a los bordes**, y aparece un **velo modal sobre toda la ventana**: tocarlo compacta la píldora, **oculta el teclado y descarta el borrador**. Sobre el campo hay una **fila de atajos de fecha** con chips: «Mañana por la mañana» (mañana a las 09:00), «Próxima semana» (dentro de 7 días, a la hora por defecto), «Algún día» (sin fecha) y «Elegir», que abre un selector de fecha. Tocar de nuevo un atajo activo lo quita; la elección se muestra como chip quitable «Para: …» y el atajo se resuelve al enviar, no al tocarlo. Un **botón de listas a la derecha del campo** abre un **panel de listas animado** (entrada y salida suaves) con el nombre de cada lista, su **contador de tareas pendientes** y la actual marcada como «Seleccionada». La lista **preseleccionada depende del contexto**: dentro de una lista, esa lista; en cualquier otro sitio, la lista por defecto (también desde `Mi día`, donde además la tarea queda marcada para hoy); con el «+» de una sección de `Próximos 7 días` la fecha de esa sección llega ya elegida. Si la lista elegida o la del contexto se ha borrado, el alta se rechaza con error visible. Tras un alta correcta se conserva la lista elegida; al cerrar la píldora se olvidan las elecciones. **Atrás** actúa en cascada: cierra primero el selector de fecha, luego el panel de listas y por último la píldora. Si el alta falla se mantiene lo escrito y se muestra el error. La píldora **no ofrece prioridad ni asignado** (la tarea se crea con prioridad Media y sin recordatorio ni repetición; se editan abriendo la tarea). La columna del tablero conserva su propio «Añadir tarea». Cambio transversal: la **navegación entre pantallas usa una transición de zoom-out con fundido** en todas las rutas (también con «Atrás»); con la escala de animaciones del sistema a 0 («Quitar animaciones») el cambio de pantalla, el velo y el panel son instantáneos. La lógica de atajos, de lista efectiva y del estado, y las funciones de movimiento de la transición, están cubiertas por tests JVM; el foco y el teclado (al tocar el botón de lista, un chip o el velo), la altura del panel con teclado, fuente grande y horizontal, el velo y la gestión de toques, el selector de fecha, las transiciones y la animación del panel, y TalkBack **no están cubiertos por pruebas automáticas**.
- **Fila de tarea única y acciones por fila**: `Mi día`, `Próximos 7 días`, `Todas las tareas` y las listas comparten la misma fila (casilla, título, prioridad, fecha y, según la pantalla, tablero, lista o estado repetido). **Deslizar hacia la derecha borra** la tarea (fondo de error con icono y «Borrar»; completar o reabrir ya no es un gesto: se hace con la casilla o la hoja) y el deslizamiento hacia la izquierda depende de la pantalla: en `Mi día` la quita de hoy, en las listas alterna Mi día y en `Próximos 7 días` y `Todas las tareas` la reprograma a «Mañana». El botón **«Más acciones»** (y la pulsación larga) abre una hoja con las mismas acciones como **alternativa accesible** (también expuestas como acciones personalizadas de accesibilidad): completar o reabrir, añadir o quitar de Mi día, reprogramar a «Mañana», «Próxima semana» o «Sin fecha» (conservando la hora local previa; sin fecha previa se usa 09:00), «Asignar a tablero», «Mover a lista…» para tareas de una lista y, siempre al final, «Borrar tarea». Las tareas repetidas no ofrecen reprogramar. La primera vez se muestra una breve pista del gesto. Los estados vacíos incluyen una acción. - **Cuenta e inicio de sesión (opcional)**: la app sigue arrancando en `Mi día` y es plenamente usable sin sesión. En `Configuración` hay una sección **«Cuenta»** con «Iniciar sesión», que abre una pantalla de login con correo y contraseña, y, con sesión, «Cerrar sesión» (con confirmación). **Al arrancar** se intenta reanudar la sesión guardada sin pedir credenciales: sin sesión guardada no se hace ninguna petición; sin red, o si el servidor no admite el flujo móvil, la app queda en modo «sin conexión con el servidor» sin tocar el token guardado. Si la sesión **expira**, se muestra un aviso con la acción «Iniciar sesión». **Cerrar sesión** limpia primero los datos de sesión locales y después avisa al servidor; si no se le puede avisar, se informa de que la sesión se cerró solo en este dispositivo. Limitación actual: el servidor aún no admite el refresco de sesión desde móvil, así que hoy un inicio de sesión correcto contra el servidor real termina en la pantalla «Versión no compatible». No hay registro de cuentas ni recuperación de contraseña, y los datos siguen siendo solo locales. La lógica (reglas, estados de sesión, errores, ViewModels, cliente de autenticación) está cubierta por tests JVM; las **pruebas manuales en dispositivo están pendientes** y el dibujo de las pantallas no está cubierto por pruebas automáticas.
- **Metadatos de sincronización**: `SyncableEntity` fija las columnas comunes de toda entidad local (id UUID de cliente, `updatedAt` en epoch ms UTC, marca `pending` y `deletedAt`) y `domain/model/SyncMetadata.kt` modela esos metadatos con sus transiciones (creación, cambio local y borrado local). `data/local/` convierte entre entidad y metadatos; los tipos de Room no salen de esa capa.
- **Dominio**: `DomainError` (tipado por código; variantes de validación, no encontrado, no autenticado, prohibido, conflicto, red, límite de peticiones, servidor y desconocido, con `fromApi` para mapear los códigos de error de la API a su variante) + `DomainResult`, conversión UTC↔zona local con `java.time` (Instant en dominio, conversión solo en presentación). El modelo `Board` y sus reglas (crear, renombrar, borrado lógico, validación del nombre), el modelo `Column` con sus reglas (crear, renombrar, reordenar con renumeración densa de posiciones y borrado lógico rechazado si la columna tiene tareas) y el modelo `Task` con sus reglas (crear, editar, borrado lógico, título obligatorio y campos opcionales normalizados) y el modelo `Subtask` con sus reglas de validación son Kotlin puro. La prioridad de una tarea es un conjunto cerrado (`LOW`, `MEDIUM`, `HIGH`, `URGENT`) y un valor desconocido almacenado degrada a `MEDIUM`.
