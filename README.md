# Taskeer

Aplicación nativa Android (Kotlin + Jetpack Compose) para gestionar tareas kanban. Esta versión es offline-first con datos locales; no incluye red ni sincronización en esta fase. Los avisos y recordatorios usan notificaciones locales del sistema.

## Requisitos

- JDK 25 (Android Studio JBR o compatible)
- Android SDK con la API 37 disponible; la ruta del SDK se define en la configuración local del entorno, que no se versiona
- Android Studio / Gradle

## Cómo compilar y ejecutar tests

```bash
./gradlew :app:testDebugUnitTest              # tests JVM
./gradlew :app:lintDebug :app:assembleDebug   # lint + build de depuración
```

La puerta de verificación son los tests JVM en `app/src/test/java/**` (JUnit 4). Los tests instrumentados (`app/src/androidTest/**`) requieren emulador y no forman parte de la puerta de verificación.

## Funcionalidades actuales (verificadas)

- **Arquitectura limpia**: capas `domain/`, `data/`, `di`, `ui/`. `domain/` es Kotlin puro (sin Android). `ui/` no accede a almacenamiento.
- **Contenedor de dependencias manual**: `di/AppContainer` creado por `TaskeerApplication`.
- **Navegación**: la app arranca en `Mi día`. Las pantallas de sección no tienen barra inferior: un **botón Home flotante** (esquina suave del tema) lleva al hub **Home** desde las pantallas de sección y desde el tablero, y desde Home una **barra de navegación estándar de Material 3**, anclada al borde inferior del hub, con iconos y nombres completos, abre `Mi día`, `Próximos 7 días`, `Todas las tareas` y `Calendario` (esta última solo muestra «Próximamente»; no hay calendario real). Home no es una pestaña: la barra no marca ninguna sección como seleccionada. Las pantallas de detalle (columnas, avisos, Configuración) usan flecha de vuelta. Hay restauración/recorte de estado según política de navegación.
- **Tema** (se configura en la pantalla `Configuración`, ya no en la barra superior): claro/oscuro/automático (`LIGHT`/`DARK`/`AUTO`). Origen de color a elección del usuario: **paleta de marca** o **Material You** (color dinámico). En API < 31 no se ofrece la opción dinámica; por defecto se usa Material You si el dispositivo lo soporta, si no se usa la paleta de marca. Las preferencias del tema se persisten con DataStore.
- **Tableros (CRUD local)**: los tableros se ven y se crean en el hub Home (ver «Home»). Se pueden **crear** (Card «+» con un diálogo), **renombrar** y **eliminar** (desde el menú de tres puntos del propio tablero, el eliminar con confirmación). El nombre se recorta y no puede quedar vacío (se rechaza con un error de validación visible); la lista se ordena por fecha de creación y se actualiza de forma reactiva. Al tocar un tablero se abre su **tablero kanban**. El borrado es lógico (soft delete): la fila permanece en la base de datos pero el tablero deja de listarse. Toda la funcionalidad es local, sin red.
- **Columnas del tablero (CRUD local)**: al crear un tablero se **siembran tres columnas por defecto** («Por hacer», «En progreso», «Hecho»; la última marcada como columna de cierre) en la misma operación atómica que crea el tablero. En la pantalla de columnas se puede **crear** (se añade al final), **renombrar**, **reordenar** con «subir»/«bajar» y **borrar**. El nombre se recorta y no puede quedar vacío; alta y renombrado se deshabilitan con el campo vacío y los movimientos se deshabilitan en los extremos de la lista. El orden se persiste por posición y se mantiene tras recargar. El borrado es lógico (soft delete) y recompacta las posiciones de las columnas restantes; el dominio rechaza borrar una columna que tiene tareas (también cuentan las borradas lógicamente) y muestra el error en pantalla. Toda la funcionalidad es local, sin red.
- **Tareas del tablero (CRUD local)**: dentro de la pantalla de columnas, cada columna ofrece **Añadir tarea** y lista las tareas que le pertenecen; cada tarea tiene una acción **Editar** que abre el editor. El editor permite fijar **título** (obligatorio: se recorta y no puede quedar vacío; con el campo vacío el botón de guardar queda deshabilitado y el dominio rechaza la escritura con un error de validación visible), **descripción** (opcional), **prioridad** (conjunto cerrado de cuatro valores — Baja, Media, Alta y Urgente — con Media por defecto, que se elige en un **desplegable**), **asignado** (el usuario local, «Yo»; el editor ya no ofrece «Sin asignar» y una tarea creada o editada sin asignado explícito queda asignada a «Yo») y **fecha límite** (opcional). La fecha límite se captura con un selector de fecha y otro de hora **en la zona horaria del usuario** y se guarda convertida a **UTC**; al reabrir una tarea existente la fecha se muestra de nuevo en la zona local. La tarea nueva se añade al final de su columna y el editor **no** ofrece selector de columna: la tarea pertenece a la columna donde se crea. El **borrado** es lógico (soft delete): la fila permanece en la base de datos marcada como borrada y deja de listarse, sin renumerar el resto. Toda la funcionalidad es local, sin red.
- **Tablero kanban**: al abrir un tablero se ven sus columnas, en orden, con las tareas de cada una como tarjetas (columna vacía con su indicación). Cada tarjeta muestra el título, la **prioridad**, la **fecha límite** (en la zona horaria del usuario), el **asignado** («Yo» para el usuario local) y una **estrella** (icono relleno/contorno) pulsable que marca o desmarca la tarea en «Mi día»; la estrella solo se ve rellena si la marca es **de hoy** (una marca de un día anterior se muestra vacía y volver a tocarla la añade a hoy) (el toque no inicia arrastre ni abre el editor). Con una **pulsación larga y arrastre** una tarjeta se **mueve a otra columna** (entre tarjetas o en una columna vacía) o se **reordena dentro de su columna**; soltar en el mismo sitio o fuera de toda columna no cambia nada. El movimiento se persiste de forma atómica con posiciones contiguas (se renumeran origen y destino, normalizando huecos) y se mantiene al reabrir la app. Mientras se guarda, la tarjeta se ve ya en destino; si el movimiento falla (tarea o columna inexistente o borrada, columna de otro tablero, índice fuera de rango) se revierte al orden guardado y se muestra el error. Pulsar una tarjeta abre el editor, «Añadir tarea» crea la tarea en esa columna y el botón «Columnas» abre la gestión de columnas. El botón «Añadir columna» abre un diálogo para crear una columna nueva (al final) sin salir del tablero, con el mismo recorte y validación del nombre que la pantalla de columnas. La pantalla de columnas incluye un botón «Volver» que regresa al tablero. Toda la funcionalidad es local, sin red. El gesto de arrastre está cubierto por tests de la lógica de destino, pero no por una prueba instrumentada.
- **Subtareas (CRUD local)**: el editor de una tarea existente incluye una sección de **subtareas** donde se puede **crear**, **editar** el título, **marcar como completada** (y desmarcar) y **borrar**. Al **crear una tarea nueva** la misma sección permite añadir subtareas como borrador (título, fecha límite y asignado opcionales; no se pueden completar durante el alta) que se guardan junto con la tarea. El borrado es lógico (soft delete) y **borrar una tarea borra también sus subtareas** en la misma operación. Cada subtarea admite además una **fecha límite** y un **asignado** opcionales (sin asignar o el usuario local; las subtareas conservan «Sin asignar»), editables desde la propia sección. El repositorio expone el **progreso** de las subtareas de una tarea (total y completadas) como flujo reactivo. Toda la funcionalidad es local, sin red.
- **Completar tareas con una casilla**: cada tarea del tablero kanban, de las listas y de `Mi día` tiene una **casilla de un toque** (con descripción accesible «Completar tarea» / «Marcar como pendiente» y área táctil de 48 dp) que la completa o la devuelve a pendiente; la tarea completada muestra el título tachado. «Completada» es un estado propio de la tarea (marca de fecha de completado, que se persiste en Room), independiente de la columna. Al **completar** una tarea de un tablero se mueve al final de la **columna de cierre** (la de menor posición si hay varias; si ya está en una, se queda) y se renumera la columna de origen; si el tablero no tiene columna de cierre, se marca en su columna sin moverla. Al **desmarcar** una tarea que está en una columna de cierre, vuelve al final de la **primera columna que no es de cierre**; si está en otra columna solo se limpia la marca, y si el tablero solo tiene columnas de cierre se rechaza con un error visible. Las tareas de una lista se marcan sin cambiar de sitio. Mover una tarea a (o desde) una columna de cierre, arrastrando o con «Asignar a tablero», también la marca o desmarca. Completar o desmarcar respeta el límite WIP de la columna destino (conflicto visible, sin cambios). Las tareas completadas **siguen en `Mi día` hasta el fin del día en que se completaron** (tachadas, al final de la lista), no cuentan como vencidas ni como tareas activas, y **no generan avisos** por fecha límite, resumen ni recordatorio manual; siguen contando en los contadores de columna del tablero. Repetir la misma acción no escribe nada. Las tareas que estaban en una columna de cierre al actualizar la app pasan a constar como completadas. Local, sin red. La migración sobre una instalación real, el dibujo de la casilla y el tachado no están cubiertos por pruebas automáticas.
- **Repetir tareas**: el editor (tarea nueva o existente) incluye un selector **«Repetir»** con «No se repite», «Cada día», «Entre semana», «Cada semana», «Cada mes», «Cada año» y «Personalizada…» (intervalo de 1 a 999, unidad día, semana, mes o año y, con semanas, los días de la semana). Requiere **fecha límite**: sin ella el selector está deshabilitado y al quitar la fecha vuelve a «No se repite»; el dominio rechaza una regla inválida o sin fecha con error visible. Al **completar** una tarea repetida se conserva y aparece **una sola vez** la siguiente, en el mismo sitio (misma columna o la misma lista; si la original pasa a una columna de cierre, la siguiente queda en la columna de origen, y completar sigue funcionando con la columna al límite WIP). La nueva fecha límite se calcula desde la fecha límite de la tarea (no desde el momento de completarla), **sin quedar antes de hoy**, en la **zona horaria del usuario** y conservando la hora local; en reglas mensuales y anuales el fin de mes se resuelve con un **día ancla** (31 de enero, 28 de febrero, 31 de marzo; 29 de febrero pasa a 28 en años no bisiestos). La siguiente copia título, descripción, prioridad, responsable, las **subtareas activas** (sin completar y con la fecha desplazada) y, si había, un **recordatorio manual con el mismo desfase** respecto a la fecha (si ya no es futuro no se crea). Desmarcar la original no crea otra y volver a completarla no duplica la siguiente. Se aplica igual al completar con la casilla, al arrastrar a una columna de cierre y al «Asignar a tablero» hacia una de cierre; la siguiente no se añade a Mi día. La tarea original y su siguiente se borran de forma independiente. La creación de la siguiente y la marca de la original se guardan en una única transacción. La lógica está cubierta por tests JVM; la migración sobre una instalación real, el cambio de horario de verano en dispositivo y el dibujo del selector **no están cubiertos por pruebas automáticas**.
- **Alta completa de tarea**: al guardar una tarea nueva se persisten juntas, de forma atómica, la tarea, sus subtareas y el recordatorio manual (hora futura); si algo falla no queda nada guardado, y cancelar o cerrar el diálogo no deja ninguna fila. Local, sin red.
- **Límites de validación**: el dominio rechaza con error de validación nombres de tablero de menos de 2 o más de 150 caracteres, nombres de columna de más de 100, títulos de tarea y de subtarea de más de 200 y descripciones de tarea de más de 5000 (tras recortar espacios).
- **Límite WIP y columna de completadas**: cada columna puede tener un límite WIP opcional, que se fija o quita desde la pantalla de columnas (campo «Límite WIP» y botón «Fijar»; vacío lo quita; el dominio rechaza valores menores que 1 con un error visible). Una columna con límite no admite más tareas activas que ese límite: **crear** una tarea en ella o **mover** una tarea desde otra columna se rechaza con un conflicto (el editor permanece abierto con el error; en el tablero la tarjeta vuelve a su sitio y se muestra el error). Reordenar dentro de la columna y sacar tareas de una columna sobrepasada siempre se permite, y las tareas borradas no cuentan. En el tablero cada columna con límite muestra un contador «n/límite», la columna de cierre se marca con un icono de completada y las tareas con fecha límite vencida (salvo las completadas) se muestran en color de error con descripción «Vencida: <fecha>». El dibujo del icono, el contador y la fecha vencida no están cubiertos por pruebas instrumentadas.
- **Mi día (diario)**: la sección `Mi día`, pantalla de arranque de la app, muestra una **lista unificada** de tareas, sin bloques fijos, que **se renueva cada día** según la **zona horaria del usuario** (el cambio de día, de zona u hora del dispositivo se detecta con la app abierta en como mucho un minuto, y los días de cambio de horario de verano duran 23 o 25 horas). Reúne las tareas **marcadas con la estrella hoy** y las asignadas al usuario local con fecha límite **hasta el fin de hoy** (vencidas y de hoy; las de fechas futuras no entran; las tareas creadas sin asignado explícito cuentan como asignadas a «Yo»); una tarea que cumple ambas condiciones aparece una sola vez. Cada fila (la fila de tarea compartida, ver más abajo) muestra título, tablero, prioridad y fecha límite en la zona del usuario, y una casilla para completarla. Una única fila de chips permite **filtrar** por todas, marcadas, asignadas o vencidas, y el menú **«Ordenar»** junto a los chips (solo en esta pantalla) ordena por fecha límite (por defecto; sin fecha al final), prioridad o marcado reciente; orden y filtro se combinan y un filtro sin resultados se distingue de una lista vacía. **Las tareas completadas hoy no desaparecen**: quedan **tachadas al final de la lista** (con cualquier orden y filtro; el filtro de vencidas no las incluye) hasta el fin del día, y al día siguiente salen; desmarcarlas las devuelve a pendientes. La cabecera muestra siempre el **contador de tareas vencidas** (asignadas al usuario local, con fecha pasada, sin contar las completadas), exacto y sin tope, y se recalcula al cambiar los datos. **Tocar la fila abre el editor de tarea** (el mismo del tablero); marcar o quitar de Mi día se hace con el deslizamiento o la hoja de acciones de la fila. Al cambiar el día, las marcas de días anteriores que siguen sin completar no se pierden: aparecen en una sección plegable **«Sugerencias de ayer»** (con su contador), sin límite de antigüedad, y cada una se puede triar con **«Mantener hoy»** (renueva la marca), **«Mañana»** (reprograma la fecha límite y quita la marca; no se ofrece en tareas repetidas), **«Completar»** o **«Descartar»** (quita la marca), tanto con el deslizamiento como desde la hoja de acciones. Las tareas ya incluidas en la lista de hoy por su fecha no se repiten como sugerencia. La marca se persiste en Room y sobrevive a reiniciar la app; el cambio de día no escribe en la base de datos. Invitaciones no se muestran. Las tareas de las listas (sin tablero) también aparecen. Toda la funcionalidad es local, sin red. La lógica está cubierta por tests JVM; el dibujo de la pantalla, los chips, el tachado, el toque de fila y el cambio de día o de zona en un dispositivo real no están cubiertos por pruebas automáticas.
- **Próximos 7 días**: sección accesible desde Home. Muestra una **sección desplegable por cada uno de los próximos 7 días** (según el día actual en la zona del usuario), cada una con su propio botón **«+»** para añadir una tarea con la fecha de esa sección. Lista las tareas no completadas ni borradas con fecha límite (también las de listas), con la fila de tarea compartida: la casilla completa la tarea, tocar la fila abre el editor. Sin tareas muestra un estado vacío. Se reagrupa al cambiar el día o la zona horaria. Local, sin red. La lógica está cubierta por tests JVM; el dibujo de la pantalla y la navegación en dispositivo no están cubiertos por pruebas automáticas.
- **Todas las tareas**: sección accesible desde Home que agrupa las tareas pendientes con fecha límite en **«Hoy»**, **«Mañana»** y **«Próximamente»**, y las que no tienen fecha en **«Algún día»**. Usa la misma fila de tarea compartida y las mismas acciones por fila. Local, sin red; sin pruebas automáticas del dibujo.
- **Píldora de alta flotante**: las pantallas de sección (`Mi día`, `Próximos 7 días`, `Todas las tareas`, `Calendario` y cada lista) muestran una **píldora flotante** compacta con un campo de **título** y un botón de **enviar** para crear una tarea al instante. Al abrirla se **expande recta, a todo el ancho de la pantalla y pegada al teclado y a los bordes**, y aparece un **velo modal sobre toda la ventana**: tocarlo compacta la píldora, **oculta el teclado y descarta el borrador**. Sobre el campo hay una **fila de atajos de fecha** con chips: «Mañana por la mañana» (mañana a las 09:00), «Próxima semana» (dentro de 7 días, a la hora por defecto), «Algún día» (sin fecha) y «Elegir», que abre un selector de fecha. Tocar de nuevo un atajo activo lo quita; la elección se muestra como chip quitable «Para: …» y el atajo se resuelve al enviar, no al tocarlo. Un **botón de listas a la derecha del campo** abre un **panel de listas animado** (entrada y salida suaves) con el nombre de cada lista, su **contador de tareas pendientes** y la actual marcada como «Seleccionada». La lista **preseleccionada depende del contexto**: dentro de una lista, esa lista; en cualquier otro sitio, la lista por defecto (también desde `Mi día`, donde además la tarea queda marcada para hoy); con el «+» de una sección de `Próximos 7 días` la fecha de esa sección llega ya elegida. Si la lista elegida o la del contexto se ha borrado, el alta se rechaza con error visible. Tras un alta correcta se conserva la lista elegida; al cerrar la píldora se olvidan las elecciones. **Atrás** actúa en cascada: cierra primero el selector de fecha, luego el panel de listas y por último la píldora. Si el alta falla se mantiene lo escrito y se muestra el error. La píldora **no ofrece prioridad ni asignado** (la tarea se crea con prioridad Media y sin recordatorio ni repetición; se editan abriendo la tarea). La columna del tablero conserva su propio «Añadir tarea». Cambio transversal: la **navegación entre pantallas usa una transición de zoom-out con fundido** en todas las rutas (también con «Atrás»); con la escala de animaciones del sistema a 0 («Quitar animaciones») el cambio de pantalla, el velo y el panel son instantáneos. La lógica de atajos, de lista efectiva y del estado, y las funciones de movimiento de la transición, están cubiertas por tests JVM; el foco y el teclado (al tocar el botón de lista, un chip o el velo), la altura del panel con teclado, fuente grande y horizontal, el velo y la gestión de toques, el selector de fecha, las transiciones y la animación del panel, y TalkBack **no están cubiertos por pruebas automáticas**.
- **Fila de tarea única y acciones por fila**: `Mi día`, `Próximos 7 días`, `Todas las tareas` y las listas comparten la misma fila (casilla, título, prioridad, fecha y, según la pantalla, tablero, lista o estado repetido). **Deslizar hacia la derecha borra** la tarea (fondo de error con icono y «Borrar»; completar o reabrir ya no es un gesto: se hace con la casilla o la hoja) y el deslizamiento hacia la izquierda depende de la pantalla: en `Mi día` la quita de hoy, en las listas alterna Mi día y en `Próximos 7 días` y `Todas las tareas` la reprograma a «Mañana». El botón **«Más acciones»** (y la pulsación larga) abre una hoja con las mismas acciones como **alternativa accesible** (también expuestas como acciones personalizadas de accesibilidad): completar o reabrir, añadir o quitar de Mi día, reprogramar a «Mañana», «Próxima semana» o «Sin fecha» (conservando la hora local previa; sin fecha previa se usa 09:00), «Asignar a tablero», «Mover a lista…» para tareas de una lista y, siempre al final, «Borrar tarea». Las tareas repetidas no ofrecen reprogramar. La primera vez se muestra una breve pista del gesto. Los estados vacíos incluyen una acción. La lógica está cubierta por tests JVM; el gesto, la hoja, el dibujo, la altura del sheet con teclado y TalkBack no están cubiertos por pruebas automáticas.
- **Borrar con deshacer**: al borrar una tarea desde la fila (deslizando a la derecha o con «Borrar tarea» en la hoja de acciones, también en las sugerencias de ayer) aparece un **snackbar** estándar «Tarea borrada» con la acción **«Deshacer»**, sobre la píldora y el botón Home, que se cierra a los **3 segundos**; un nuevo borrado sustituye al anterior (solo el último es deshacible). **Deshacer** restaura la tarea (borrado lógico) con las subtareas borradas en la misma operación y su recordatorio manual si sigue siendo futuro (uno vencido sigue descartado), en su misma posición si está libre o al final si no; si el destino ya no es válido (columna borrada o con el límite WIP lleno) no se restaura nada y se muestra el error «No se puede deshacer: …». **Limpiar** también ofrece «N tareas borradas» con **Deshacer**, que restaura todo el lote o nada. La restauración no duplica marcas de Mi día ni la siguiente tarea de una repetición. Local, sin red. La lógica está cubierta por tests JVM; el gesto, el snackbar, su posición con teclado y TalkBack no están cubiertos por pruebas automáticas.
- **Animación al completar**: al completar con la casilla esta rebota, el título se tacha de izquierda a derecha y se atenúa; tras una **pausa breve (500 ms)** la fila se mueve al final en `Mi día` y en las listas, o se desvanece y colapsa en `Próximos 7 días` y `Todas las tareas`; reabrir es inmediato. Con «Quitar animaciones» del sistema (escala 0) todo es instantáneo. Limitación conocida: en las vistas por fecha, un borrado hecho durante esos 500 ms deja la fila visible tachada hasta que termina la pausa. La animación no está cubierta por pruebas automáticas.
- **Pantalla de lista**: al abrir una lista propia desde Home se muestran sus tareas (la más reciente primero), con la fila compartida, la píldora de alta y la acción **«Asignar a tablero»** (desde la hoja de acciones de la fila, también en Mi día), que se elige en un **bottom sheet** y respeta el límite WIP de la columna destino. Las tareas de una lista no aparecen en el tablero kanban ni se pueden mover como tareas de un tablero.
- **Listas de tareas**: además de los tableros, las tareas pueden vivir en **listas planas propias** (sin columnas). Al instalar o actualizar se crea de serie una lista llamada «Tareas», que **no es especial**: se puede renombrar y borrar, salvo que sea la última lista (nunca hay 0 listas). La **lista por defecto** es la primera por orden; las tareas creadas sin destino van a ella. Las listas se ven en el hub Home (ver «Home») con su **contador de tareas pendientes**; el mosaico «+» las **crea**, y desde el menú de tres puntos de una lista se puede **renombrar** y **eliminar** (nombre recortado, de 1 a 100 caracteres y sin repetirse entre listas, sin distinguir mayúsculas). Al **borrar** una lista, la confirmación indica a qué lista pasan sus tareas y estas se mueven al final de la lista por defecto resultante, en una sola operación. Desde la hoja de acciones de una tarea la acción **«Mover a lista…»** la cambia de lista. Una tarea está en **una lista o en un tablero, no en ambos**: «Asignar a tablero» la saca de su lista. Las tareas repetidas dejan la **siguiente** en la misma lista. El **nombre de la lista** aparece en las filas de `Mi día` y de `Próximos 7 días` (en lugar del tablero) y estas tareas siguen entrando en Mi día, en las vistas por fecha y en los avisos. Local, sin red. La lógica y las consultas están cubiertas por tests JVM; el dibujo de los diálogos y la hoja «Mover a lista…» y la migración 13→14 sobre una instalación real no están cubiertos por pruebas automáticas.
- **Home (hub)**: pantalla con un **buscador** a todo el ancho (campo visible, **aún sin función**; indica «Próximamente»), la sección **«Listas propias»** en mosaicos con contador y un mosaico **«+»** para crear lista, la sección **«Workspaces»** con los tableros en mosaicos y una Card **«+»** que abre un diálogo para crear tablero, y la barra de navegación de 4 secciones en la parte inferior. Workspaces es solo el nombre de la sección de tableros locales: no hay compartición ni red.
- **Barra superior y menú de tres puntos**: las pantallas de sección muestran los **avisos** a la izquierda y un menú de tres puntos. Funcionan: **Limpiar** (borra, de forma lógica, las tareas completadas tras una confirmación que indica cuántas son, con **Deshacer** posterior), **Ajustes** y, según la pantalla, **renombrar/eliminar lista** o **renombrar/eliminar tablero**. **Aún sin función** (marcados «próximamente» o «WIP»): **Sincronizar**, **Imprimir**, **Compartir**, y los ítems **Filtrar**, **Ordenar** (en `Próximos 7 días` y `Todas las tareas`) y **Mis calendarios**. `Mi día` conserva sus propios chips de filtro y su menú «Ordenar» junto a la lista, que sí funcionan.
- **Recordatorios locales**: tres mecanismos independientes, todos locales y sin red. (1) **Aviso por fecha límite**: se activa en Configuración y avisa de las tareas con fecha límite (no borradas y no completadas) con una **antelación global** a elegir entre «A la hora», 15 minutos, 1 hora o 1 día antes. (2) **Resumen programado**: en Configuración se eligen los **días de la semana** (el conjunto vacío es válido y no avisa) y la **hora**; la notificación indica cuántas tareas activas hay («Tienes N tareas activas», «No tienes tareas activas»). (3) **Recordatorio manual**: el editor (tanto de una tarea existente como de una nueva) incluye la sección **Recordatorio** con cuatro atajos: «Más tarde hoy» (ahora + 5 horas), «Mañana» y «Próxima semana» (a la **hora por defecto** configurable en Configuración, 09:00 inicialmente) y «Personalizado…» con selector de fecha y hora. En una tarea nueva el recordatorio se elige antes de guardar. Cada tarea admite **un solo recordatorio manual pendiente**; se puede cancelar (la fila se conserva como descartada) y entonces se puede crear otro. Cambiar la hora por defecto no modifica recordatorios ya creados. Las horas se interpretan en la zona del usuario y se guardan en UTC; la hora de un recordatorio manual debe ser posterior al momento actual. Una tarea completada o borrada no genera avisos, y borrar una tarea descarta sus recordatorios pendientes. Un aviso vencido hace una hora o más no se notifica y cada aviso se emite una sola vez. Se programa **una única alarma aproximada** con `AlarmManager` (`setAndAllowWhileIdle`, puede retrasarse por Doze) para el siguiente instante de entre los tres mecanismos, y se **reprograma** tras reiniciar el dispositivo y al cambiar la hora o la zona horaria del sistema. Las notificaciones usan el canal «Recordatorios». Se solicita el permiso `POST_NOTIFICATIONS` (Android 13+) cuando hay algo que avisar; si las notificaciones están desactivadas se muestra, en Configuración y en la sección «Recordatorio» del editor, el aviso «Las notificaciones están desactivadas en el sistema; no verás los avisos» con un botón «Abrir ajustes» que abre los ajustes de notificaciones de la app, y activar los avisos o crear recordatorios sigue funcionando. La lógica está cubierta por tests JVM; la **comprobación en dispositivo** (notificación con la app cerrada, reinicio, cambio de zona u hora, permiso denegado) y el dibujo de las pantallas **no están cubiertos por pruebas automáticas**.
- **Visor interno de notificaciones («Avisos»)**: cada aviso que la app emite (por fecha límite, resumen programado o recordatorio manual) se guarda en un **historial persistido en Room**, también si el sistema no llega a mostrarlo (la entrada se marca «No se mostró en el sistema»). La barra superior tiene un botón **«Avisos»** con una **insignia** con el número de no leídas (se oculta con cero y muestra «99+» a partir de 100). El visor lista las entradas de la más reciente a la más antigua, con fecha en la zona del usuario, y distingue **leídas y no leídas** («Nuevo»). Se puede **marcar una entrada como leída**, **marcar todas como leídas**, **borrar una** y **«Borrar todo»**, este último con un diálogo de confirmación que indica cuántos avisos se borran y cuántos están sin leer. El historial conserva como máximo **200 entradas**: al superarlo se ocultan las más antiguas. El borrado es lógico (soft delete). **Tocar una entrada abre la tarea** en el editor (si la tarea ya no existe se avisa) y **tocar la notificación del sistema abre el visor**. El aviso «Las notificaciones están desactivadas en el sistema; no verás los avisos» con «Abrir ajustes» también aparece en el visor. La lógica está cubierta por tests JVM; la **comprobación en dispositivo** (apertura en frío y en caliente desde la notificación, rotación, permiso y actualización desde la versión 9 de la base de datos) y el dibujo de la pantalla **no están cubiertos por pruebas automáticas**.
- **Pulido de interfaz**: presentación compacta y coherente en todas las pantallas (Home, listas, tableros, columnas, tablero kanban, Mi día, editor de tareas, Configuración y visor de avisos), con espaciados tomados de tokens comunes, divisores entre filas y componentes compartidos. Las acciones repetitivas (crear, guardar, cancelar, subir/bajar, borrar, quitar fecha, volver, estrella, etc.) usan **iconos con descripción accesible** (el mismo texto que anunciaba antes la acción) en lugar de botones de texto; Guardar, Cancelar y Borrar del editor siguen como texto, y la prioridad del editor se elige en un desplegable. Las áreas táctiles de las acciones mantienen un mínimo de 48 dp. No cambia el comportamiento ni los datos. Las reglas de presentación (sin `dp` literales en pantallas, iconos solo desde los componentes compartidos, descripción obligatoria en iconos de acción, sin glifos de texto como icono) están cubiertas por tests JVM; el aspecto visual, el tamaño de fuente al 130 % y TalkBack **no están cubiertos por pruebas automáticas**. La dependencia de iconos aumenta el APK de depuración (sin minificar).
- **Datos locales**: preferencias (tema, origen de color y ajustes de recordatorios) en DataStore, y tableros, listas, columnas, tareas, subtareas, marcas de «Mi día», recordatorios manuales y avisos del visor persistidos en Room.
- **Capa de datos local (Room)**: `AppDatabase` (`taskeer.db`, versión 14) con migraciones explícitas no destructivas (la migración a la versión 2 añade la fecha de creación del tablero, la de la versión 3 crea la tabla de columnas y la de la versión 4 crea la tabla de tareas con su índice por columna y posición la de la versión 5 crea la tabla de subtareas y la de la versión 6 añade a subtareas la fecha límite y el asignado, y a columnas, tareas y subtareas la fecha de creación `createdAt`, inicializada con el valor de `updatedAt` en las filas existentes, la de la versión 7 crea la tabla de marcas de «Mi día» la de la versión 8 asigna «Yo» a las tareas activas que no tenían asignado y la de la versión 9 crea la tabla de recordatorios manuales la de la versión 10 crea la tabla de notificaciones del visor interno y la de la versión 11 hace nulable la columna de la tarea para admitir tareas sin tablero, y la de la versión 12 añade a las tareas la marca de completada, rellenada para las tareas activas que estaban en una columna de cierre, y la de la versión 13 añade a las tareas cinco columnas nulables con la regla de repetición y el enlace a la siguiente tarea, y la de la versión 14 crea la tabla de listas, siembra la lista «Tareas» y añade a las tareas el identificador de lista, rellenado en las tareas que no tenían tablero, sin perder datos) y esquema exportado (versiones 1 a 14) en `app/schemas/`. `BoardDao`, `ColumnDao`, `TaskDao` y el DAO de subtareas siguen las convenciones del proyecto: observación reactiva con `Flow`, lecturas puntuales y escrituras `suspend`, exclusión de filas borradas en los listados, orden estable por posición con desempate por id y borrado lógico (soft delete) sin borrado físico. La siembra de columnas al crear un tablero se hace en una sola transacción (tablero + columnas). La base está cableada a la UI mediante `BoardRepository`, `ColumnRepository`, `TaskRepository`, `SubtaskRepository`, `MyDayRepository` y `ReminderRepository`, `TaskListRepository` y `NotificationHistoryRepository`, que definen operaciones con tipos de dominio (`Flow<List<…>>` y `suspend`). El listado de tareas de un tablero se resuelve en el DAO con una unión con la tabla de columnas, de modo que se excluyen tanto las tareas borradas como las columnas borradas.
- **Metadatos de sincronización**: `SyncableEntity` fija las columnas comunes de toda entidad local (id UUID de cliente, `updatedAt` en epoch ms UTC, marca `pending` y `deletedAt`) y `domain/model/SyncMetadata.kt` modela esos metadatos con sus transiciones (creación, cambio local y borrado local). `data/local/` convierte entre entidad y metadatos; los tipos de Room no salen de esa capa.
- **Dominio**: `DomainError` (tipado por código; variantes de validación, no encontrado, no autenticado, prohibido, conflicto, red, límite de peticiones, servidor y desconocido, con `fromApi` para mapear los códigos de error de la API a su variante) + `DomainResult`, conversión UTC↔zona local con `java.time` (Instant en dominio, conversión solo en presentación). El modelo `Board` y sus reglas (crear, renombrar, borrado lógico, validación del nombre), el modelo `Column` con sus reglas (crear, renombrar, reordenar con renumeración densa de posiciones y borrado lógico rechazado si la columna tiene tareas) y el modelo `Task` con sus reglas (crear, editar, borrado lógico, título obligatorio y campos opcionales normalizados) y el modelo `Subtask` con sus reglas de validación son Kotlin puro. La prioridad de una tarea es un conjunto cerrado (`LOW`, `MEDIUM`, `HIGH`, `URGENT`) y un valor desconocido almacenado degrada a `MEDIUM`.
